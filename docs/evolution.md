# 执行与进化

## 一次运行

```
任务 ─► 匹配技能（本地词法 / 向量召回 → 小模型判定 + 抽取参数，一次调用）
  ├─ 命中流程型 → 执行脚本：guard → 各步骤 → verify
  │     ├─ 成功 → 完成（mode=skill，最快、最省）
  │     └─ 第 k 步失败 → 强模型从第 k 步接管（知道已完成的步骤和已发生的副作用，不重复执行）（mode=skill_takeover）
  ├─ 命中指南型 → 把 SKILL.md 正文注入提示词，AI 照着做（mode=guide）
  └─ 未命中 → AI 自由执行，只能通过工具行动，产生结构化轨迹（mode=freeform）
```

| mode | 含义 | 计入技能统计 | 触发进化 |
|---|---|---|---|
| `skill` | 脚本独立完成 | ✅ | 影子比对 |
| `skill_takeover` | 脚本失败、AI 接管完成 | ✅（算脚本失败） | 修补 |
| `guide` | AI 照着指南完成 | ✅ | 升级为脚本 |
| `freeform` | AI 自己完成 | — | 提炼新技能 |
| `aborted` | 用户拒绝确认 / 取消输入 | ❌ | ❌ |
| `error` | 意外错误（如 LLM 调用失败）：留下记录，异常照常抛出 | ❌ | ❌ |

- **模型分层**：高频的匹配、参数抽取、脚本内 `ctx.llm` 用 fast 模型；低频的接管、提炼、修补用 strong 模型。技能库为空或没有召回候选时，不调用匹配模型。
- **verify 防止"静默错误"**：脚本跑完但 verify 不通过，同样交给 AI 接管。
- **guard 防止"做了一半"**：前置检查不通过时一个步骤都不执行，直接交给 AI，避免在错误的环境里执行了一半有副作用的操作。
- **接管与自由执行必须用 `finish` 提交结果**：调用过工具之后只回一段文字不算完成（纯问答类任务除外）。
- **执行环境故障**：脚本 worker 无法启动时，降级为 AI 自由执行，不计入技能统计、不触发进化。

## 后台进化

进化器在后台串行处理任务，不增加用户的等待时间（[engine/evolver.py](../src/no_agent/engine/evolver.py)）：

| 触发 | 任务 | 做什么 |
|---|---|---|
| 接管成功 | `patch` | 参考接管过程，**只重写出错的那个步骤函数**；偶发故障（网络抖动）可以判定为不需要修改 |
| 用户负反馈（脚本自认为成功） | `feedback` | 修补脚本并加强 verify |
| 同类自由执行轨迹 ≥ `distill_min_traces` 条 | `distill` | 提炼参数化的新技能 |
| 指南型技能被成功使用 ≥ `distill_min_traces` 次 | `upgrade` | 从使用轨迹提炼流程脚本，作为候选挂到同一个技能上 |
| 每次真实运行成功后 | `shadow` | 用这次的录制数据跑候选版本，与真实结果比对 |

反馈入口：`agent.feedback(run_id, score, comment)`、HTTP `POST /api/v1/feedback`、MCP 工具 `feedback`。

### 技能怎么"长"出来

```
AI 自由执行 ─(同类任务成功 N 次)─► 提炼 ─┐
                                        ├─► 多个候选脚本 → 回放测试 → 选最好的 → 影子运行 → 转正
指南型技能 ─(被成功使用 N 次 = 热度)─► 升级 ─┘                                          （流程型）
流程型 ─(失败 → AI 接管)─► 只修补出错的步骤 → 回放测试 → 影子运行 → 转正
```

- **多候选提炼**：一次生成 `distill_candidates` 个（默认 2）思路不同的候选，按"测试通过率 → `ctx.llm` 调用点越少越好（更确定、更省） → 代码越短越好"选出最好的
- **按热度升级**：转正前仍按指南执行，转正后直接跑脚本；候选的参数 schema 和权限记在候选版本上，转正时才应用到技能。原指南保留，自动追加"自动执行"说明

## 上线门禁

新版本（修补 / 提炼 / 升级）要依次通过：

1. **回归测试**：用录制的用例回放。新版本必须通过新用例，且历史用例通过率 ≥ `promote_min_pass_rate`；不通过会带着失败信息重试，最多 `patch_max_attempts` 次。
2. **变更审查**：扩大了能力的版本等人批准，见 [安全模型](security.md#自动上线前的变更审查)。
3. **影子运行**：新版本先成为候选，不对外生效。之后每次真实运行结束，后台用这次的录制数据跑候选（不执行副作用、不弹问题），与真实交付的结果比对：一致直接算通过，不一致由小模型判断是否等价。一致 `shadow_min_runs` 次自动转正，失败超过 `shadow_max_failures` 次淘汰。淘汰原因会告诉下一次修补，避免重复犯错。`shadow_min_runs=0` 表示测试通过即上线。

### 录制回放

运行时每次工具调用都会录进轨迹，作为测试和影子运行的输入（[tools/base.py](../src/no_agent/tools/base.py) 的 `ReplayToolbox`）：

- 参数完全一致的调用 → 返回录制结果；同样参数录制了多次（如轮询）时按录制顺序依次回放
- 有副作用（`side_effect`）/ 需确认（`confirm`）的调用 → 不真正执行，返回 dry run 标记
- 依赖实时状态（`stateful`，如浏览器工具）的调用 → 没有录制就报错，绝不真实执行
- 交互式工具（提问）→ 使用录制的回答，不会再弹问题
- 其他只读调用 → 真实执行

**自定义工具务必正确标注 `side_effect` 和 `stateful`**，否则后台测试可能产生真实的副作用，或去操作用户正在使用的环境。

## 下线与回滚

- **自动下线**：当前版本最近 `retire_window` 次中脚本独立成功率低于 `retire_min_success_rate` → `retired`。有修补候选正在影子运行时暂不下线，等候选转正或被淘汰。
- **手动下线**（`POST /api/v1/skills/{id}/retire`）会一并淘汰候选版本。
- 任意历史版本都可以切换回去：`POST /api/v1/skills/{id}/activate`。
